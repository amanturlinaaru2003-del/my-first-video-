# Мультик: рисованная история под голос

`<skill>` — папка этого файла (путь показан при загрузке скилла как base directory). Запускать Python как `python`,
а если такой команды нет — `python3`. Папка ролика — та, которую назвал пользователь, иначе новая папка с названием
ролика в текущей рабочей папке. Папку плагина не менять: все файлы ролика живут в папке ролика.

Перед первым роликом в сессии прочитай `reference/style-guide.md` и посмотри лист кадров `reference/demo_sheet.jpg`.

Суть: **1 фраза = 1 сцена 1,5–3,5 с, в сцене нарисовано то, что звучит.** Человечки простые, мир богатый и тёплый,
камера едет, между сценами растворение 0,13 с, в одной точке кадра белое слово с чёрной обводкой.

## Что нужно от пользователя

Голос (`.wav/.mp3/.mp4`) **или** тема/сценарий. Больше ничего не просить: рисовка, эффекты и музыка есть.
Своя музыка пользователя — по желанию. Если голоса нет, написать сценарий (шаг 1) и попросить записать озвучку.

## Первый запуск

```
python <skill>/scripts/new_project.py --check
```
Покажет, чего не хватает (Node.js 18+, ffmpeg, numpy, faster-whisper), и команды установки. Предложи пользователю
поставить недостающее и ставь после его согласия. Первый рендер скачивает зависимости Remotion и браузер для рендера:
около 500 МБ, один раз на компьютер, в `~/.montazh-multik`. Модель распознавания (около 500 МБ) скачивается при первой
расшифровке. Об этом предупредить заранее.

## Порядок работы

1. **Сценарий** (если дали тему): 160–190 слов на ~60 с. Структура в `style-guide.md` §8: крючок-парадокс за 3 с →
   насмешка окружающих → вопрос зрителя → секрет по кусочкам с шутками → кульминация → «Дело в том, что…» → панчлайн
   с отсылкой к началу. Настоящее время, конкретные смешные цифры. Факт в объяснении проверить в интернете.
   Сразу придумать картинку к каждой фразе. Если пользователь дал свой текст, текст не менять.

2. **Голос.** В папке ролика:
   ```
   python <skill>/scripts/transcribe.py "<голос>" words.json
   ```
   Прочитать расшифровку, написать `plan_voice.json` по `templates/plan_voice.example.json`: `takes` — куски записи,
   которые войдут в ролик (при нескольких дублях — последний чистый), `max_gap` 0,08–0,12, ошибки распознавания
   поправить в `subs.fix` или `subs.replace`.
   ```
   python <skill>/scripts/prep.py plan_voice.json
   python <skill>/scripts/check_speech.py _work_multik/voice.wav
   ```
   Повторять, пока не будет «Повторов и обрывков не найдено». Намеренный повтор оставить через `cuts.keep_repeats`.
   Получаются `_work_multik/voice.wav` и `words_out.json`. Громкость голоса оценить `audio_check.py`, при тихой записи
   поднять через `voice_gain_db` в плане голоса.

3. **Раскадровка.** Написать `plan.json` по `templates/plan.example.json`, в `scenes` пока одна сцена, и получить номера слов:
   ```
   python <skill>/scripts/assemble.py plan.json --words
   ```
   Разбить на сцены по фразам и придаточным (4–8 слов). Для каждой: `id`, `at_word` (первое слово), `say`.
   Каждое существительное видно в момент, когда звучит. Соседние сцены различаются крупностью или местом. 1–3 сюжетных
   перехода. Свет меняется по драматургии. Показать пользователю таблицу «сцена / фраза / что в кадре / гэг», если он
   хочет согласовать, а затем продолжать.
   ```
   python <skill>/scripts/new_project.py .
   python <skill>/scripts/make_times.py plan.json
   ```

4. **Сцены.** Писать в `engine/src/shots.tsx`: по компоненту на сцену, порядок в `SHOTS` как в `scenes`, большие ролики
   можно делить на файлы. Образцы в `engine/src`:
   - `demo_lift.tsx` — короткий фильм целиком, основной образец. Сначала прочитай его;
   - `scene_dentist.tsx` — подробная комната с перспективой, лучами и глубиной резкости;
   - `kit.tsx` — камера `Cam`, позы `arms()`/`P`, герои `Hero`/`Suit`, реквизит, фоны `Sky`/`Room`/`Window`,
     свет `Beam`/`Bloom`, эффекты (`Confetti`, `Puffs`, `Burst`, `SpeedLines`, `Rain`, `FightCloud`…), надписи `Sign`/`FitText`;
   - `people.tsx` — человечек `Person`: лица, взгляд, позы, шапки, пот.

   Сцена получает `t` (секунды от начала сцены), `d` (длина), `w(i)` (время слова номер i от начала сцены). Действия
   привязывай к словам через `w(i)`: на нужном слове предмет появляется, лицо меняется, удар приходит.
   **Набор и образцы — только база.** Под каждую фразу придумывай своё место, реквизит и гэг, дорисовывай новые предметы,
   шапки и лица. Каждую сцену монтируй от смысла текста, а не подбирай похожую из готовых.

5. **Проверка кадров.** Номера кадров = секунды × 30. Взять середину каждой сцены и моменты ударов:
   ```
   python <skill>/scripts/render_scene.py Film . --stills 40,100,200,300
   ```
   Открыть `_work/sheet.jpg` и проверить каждый кадр: важное видно, головы и руки не закрыты предметами и не обрезаны,
   полоса субтитра на 0,70 высоты читается, нижние 20 % кадра спокойные. Исправить и повторить.

6. **Рендер и сборка:**
   ```
   python <skill>/scripts/render_scene.py Film . --out film.mp4
   python <skill>/scripts/assemble.py plan.json
   ```
   Звуки лежат в `<skill>/assets/sfx` (whoosh, pop, click, hit, ding, boing, paper, steps, sad, fanfare), музыка —
   `<skill>/assets/music/playful.mp3`. В плане указывать абсолютный путь. Эффекты — в `sfx` единственного шота `film`, `at`
   считается от начала ролика. Не хватает звука — синтезировать новый по образцу `scripts/make_audio.py`.

7. **Проверки итога:**
   ```
   python <skill>/scripts/check_speech.py "<итог>.mp4"
   ffmpeg -i "<итог>.mp4" -vf "fps=1,scale=216:-1,tile=10x6" -frames:v 1 _work/list.jpg
   ```
   Слова не повторяются; на листе нет двух одинаковых кадров подряд; субтитр в одной точке; надписи внутри предметов.
   Голос чётко слышен, музыка тихо на фоне, но слышна: обычно на 12–15 дБ тише голоса. Уровни подбираются под запись:
   замерить, послушать по цифрам, поправить `music.volume` и `sfx_volume`.

8. **Отчёт:** путь к итогу, длина, сколько сцен, какие уровни звука и почему, что не удалось проверить.

## Правила

- **Текст в мире не больше предмета.** Надпись на табличке, листке, бейдже, экране — только через `Sign` или `FitText`
  с `maxW` = ширина предмета минус поля 12–15 px с каждой стороны. Голый `<text>` — только для надписей в воздухе
  (БАЦ!, ♪). На листе кадров проверять глазами.
- Субтитры по одному слову (короткое служебное — со следующим), в одной точке, без анимации, без точек и запятых в конце.
- В речи нет запинок и случайных повторов, это проверено дословной расшифровкой итога.
- Без фиксированного стандарта громкости: замер под каждый ролик.
- Чужие кадры, персонажей, логотипы и мемы в ролик не вставлять: всё рисуем сами. Настоящие бренды не копировать.
- Конец на панчлайне, без призыва и заставки, если пользователь не попросил другое.
- Если пользователь просит правку, менять только её и пересобирать затронутое. При смене голоса или `scenes` снова
  запустить `make_times.py`.

## Справка по assemble.py

```
python <skill>/scripts/assemble.py plan.json --words      # слова с номерами
python <skill>/scripts/assemble.py plan.json --animatic   # вместо картинки карточки с текстом: проверка ритма
python <skill>/scripts/assemble.py plan.json --fast --stills 1,5,12   # черновик 540×960 + _work_multik/stills.jpg
python <skill>/scripts/assemble.py plan.json              # итог 1080×1920, 30 к/с, H.264, AAC
```
Запуск из папки ролика. Поля шота: `id`, `at_word`/`at`, `media` (путь от `work_dir` или абсолютный), `from`, `speed`,
`move` (`push pull left right up down push_up slam none`), `sfx` [`file`, `at`, `vol`]. Общие поля: `subs` (`size` 90, `y` 0,70,
`outline` 5, `shadow` 3, `max_words` 2, `short` 3, `strip_end_punct`), `music` (`file`, `from`, `volume`), `sfx_volume`,
`grade` (`sat`, `contrast`, `vignette`), `xfade`, `tail`, `out`. Шрифт субтитров Montserrat ExtraBold лежит в `fonts/`.

## Если пользователь хочет картинку нейросетью

По умолчанию всё рисуется кодом, это бесплатно. Рисовка кодом проще настоящего 3D. Если пользователь сам просит более
объёмную картинку и у него есть генератор (картинка → видео), отдай ему таблицу шотов с промптами по `templates/prompts.md`,
а готовые файлы подключи как `media` у шотов в `plan.json` (отдельный шот на каждую фразу вместо одного `film`). Платную
генерацию запускать только после его согласия, заранее назвав число шотов и цену.

## Частые сбои

- `tsc` падает в `render_scene.py`: ошибка типов в сцене, скрипт печатает строку. Исправить в `engine/src`.
- `No filter named subtitles` или `drawtext`: сборка ffmpeg без libass/freetype, нужна полная.
- Сцена короче 0,4 с: поправить `at_word` в `scenes`.
- Кириллица в субтитре квадратами: проверить, что рядом со скриптами цела папка `fonts`.
